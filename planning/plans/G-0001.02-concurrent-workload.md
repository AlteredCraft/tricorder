# G-0001.02. Concurrent workload

Status: In progress
Goal: [G-0001](G-0001-trustworthy-live-investigation.md) — instruments stay responsive and lossless together.
ADRs: [0007](../adrs/ADR-0007-bounded-camera-fifo.md), [0008](../adrs/ADR-0008-jpeg-error-path-fail-stop.md), [0009](../adrs/ADR-0009-owned-preview-and-render-placement.md)

## Hypothesis

The firmware can run camera preview, mic acquisition + FFT, IMU, touch UI and Wi-Fi transfer at the same time without losing measurement samples or building up unbounded latency.

**Refuted if:** there is an unexplained audio gap, hidden capture loss, unbounded queue growth, a failed allocation, a watchdog/reset, or timing targets fail on repeat. Lowering rates is a new run, not a retroactive pass.

## Checks

Profile: camera 1280×720 @ 30 fps (640×480 is unsupported), 48 kHz 16-bit audio, 2048-pt FFT @ 20 Hz, IMU 100 Hz, animated UI 30 fps, one JPEG every 2 s, mono audio stream + 10 Hz telemetry upload.

1. [open] Isolated 60 s baselines per stream, with produced/consumed/dropped counters.
2. [open] **Three 10-minute combined runs** with 100 input events each: zero unexplained audio gaps/allocation failures/crashes; UI frame interval p95 ≤ 50 ms, max ≤ 200 ms; input-to-submit p95 ≤ 100 ms; queues stay bounded.
3. [open] A 10 s receiver stall keeps local acquisition and UI on target. Preview drops are counted; measurement loss fails the run.
4. [open] After repeated mode cycles, free memory returns to within 5% of the post-warmup baseline.

## Observed

- 2026-09-20 — [C1] Audio 60 s: 6,000 blocks, zero loss, read p95 10.0 ms, FFT 20 Hz. Evidence: `live-audio-1`, `camera-baseline-1` · `1125cdd`.
- 2026-09-20 — [C1] Camera 60 s: 1,800 frames @ 29.999 fps, p95 33.3 ms. Evidence: `camera-baseline-1` · `1125cdd`.
- 2026-09-20 — [C1] IMU: 6,000 checked polls @ 100 Hz, zero errors. Evidence: `imu-baseline-1` · `6079c55`.
- 2026-09-20 — [C1] UI: first run 28.6 fps (failed; Mac sleep also dropped serial). After a timer-drift fix: 30.30 fps, p95 47.2 ms. Evidence: `ui-baseline-2` · `557ddb1`.
- 2026-09-20 — Camera + JPEG failed: 57 frames lost while the JPEG source copy held buffers about 70 ms. Evidence: `jpeg-baseline-1` · `8c98c00`.
- 2026-09-21 — [C1] Four buffers fixed the loss, but the vendor done-list delivered newest-first. FIFO receive passes: 1,800 ordered frames, 30 JPEGs decode. Evidence: `jpeg-ring-1`, `jpeg-fifo-1` · `9857c89`. → ADR-0007
- 2026-09-21 — A queued JPEG timeout can unwind with a stale DMA descriptor; the guard aborts first. A user-approved fault test confirmed it. Evidence: `jpeg-timeout-1`, `jpeg-guard-2` · `8efbc8c`. → ADR-0008
- 2026-09-21 — [C1] Live preview: first run lost 7 frames (core0 contention); LVGL on core1 fixed it, and an explicit LVGL wake cut first frame 304 → 121 ms. 1,800 frames, preview 14.5 fps, max gap 186 ms. Evidence: `preview-wake-1` · `11bb278`. → ADR-0009
