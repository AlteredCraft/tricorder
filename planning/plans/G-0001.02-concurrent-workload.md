# G-0001.02. Concurrent workload

Status: In progress
Goal: [G-0001](G-0001-trustworthy-live-investigation.md) — instruments stay responsive and lossless together.
ADRs: [0007](../adrs/ADR-0007-bounded-camera-fifo.md), [0008](../adrs/ADR-0008-jpeg-error-path-fail-stop.md), [0009](../adrs/ADR-0009-owned-preview-and-render-placement.md)

## Hypothesis

The firmware can run camera preview, mic acquisition + FFT, IMU, touch UI and Wi-Fi transfer at the same time without losing measurement samples or building up unbounded latency.

**Refuted if:** there is an unexplained audio gap, hidden capture loss, unbounded queue growth, a failed allocation, a watchdog/reset, or timing targets fail on repeat. Lowering rates is a new run, not a retroactive pass.

## Checks

Profile: camera 1280×720 @ 30 fps (640×480 is unsupported), 48 kHz 16-bit audio, 2048-pt FFT @ 20 Hz, IMU 100 Hz, animated UI 30 fps, one JPEG every 2 s, mono audio stream + 10 Hz telemetry upload.

1. [open] Isolated 60 s baselines per stream, with produced/consumed/dropped counters.
2. [open] **Three 10-minute combined runs** with 100 input events each: zero unexplained audio gaps/allocation failures/crashes; UI frame interval p95 ≤ 50 ms, max ≤ 200 ms; input-to-submit p95 ≤ 100 ms; queues stay bounded.
3. [open] A 10 s receiver stall keeps local acquisition and UI on target. Preview drops are counted; measurement loss fails the run.
4. [open] After repeated mode cycles, free memory returns to within 5% of the post-warmup baseline.

## Observed

- 2026-09-20 — Audio 60 s: 6,000 blocks, zero loss, read p95 10.0 ms, FFT 20 Hz (`live-audio-1`; repeated in `camera-baseline-1`).
- 2026-09-20 — Camera 60 s: 1,800 frames @ 29.999 fps, p95 33.3 ms (`camera-baseline-1`).
- 2026-09-20 — IMU: 6,000 checked polls @ 100 Hz, zero errors (`imu-baseline-1`).
- 2026-09-20 — UI: first run 28.6 fps (failed rate; Mac sleep also dropped serial). After a timer-drift fix: 30.30 fps, p95 47.2 ms (`ui-baseline-2`).
- 2026-09-20 — Camera + JPEG failed: 57 frames lost while JPEG source copy held buffers about 70 ms (`jpeg-baseline-1`).
- 2026-09-21 — Four buffers fixed the loss but the vendor done-list delivered newest-first (`jpeg-ring-1`). FIFO receive passes: 1,800 ordered frames, 30 JPEGs decode (`jpeg-fifo-1`). → ADR-0007.
- 2026-09-21 — A queued JPEG timeout can unwind with a stale DMA descriptor. The guard aborts first; user-approved fault test confirmed it (`jpeg-timeout-1`, `jpeg-guard-2`). → ADR-0008.
- 2026-09-21 — Live preview: first run lost 7 frames (core0 contention); LVGL on core1 fixed the loss but first frame took 304 ms; an explicit LVGL wake brought it to 121 ms. 1,800 frames, preview 14.5 fps, max gap 186 ms (`preview-wake-1`). → ADR-0009.

## Open

1. Isolated 60 s baseline for the mono audio stream + 10 Hz telemetry upload (C1; camera, JPEG, preview, audio, IMU and UI are done).
2. Replace the diagnostic 6 MiB/30-JPEG retention pool with recycling, needed before 10-minute camera runs.
3. Three 10-minute combined runs (C2).
4. 10 s receiver stall (C3).
