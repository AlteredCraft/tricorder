# G-0002.01. Guided A/B vertical slice

Status: In progress
Goal: [G-0002](G-0002-thin-investigation-slice.md) — one usable handheld loop.
ADRs: [0010](../adrs/ADR-0010-device-owned-ab-lan-experiment.md), [0011](../adrs/ADR-0011-bounded-tcp-write-completion.md), [0012](../adrs/ADR-0012-live-prose-over-verified-summaries.md); reuses 0003–0009.

## Hypothesis

One explicit-turn A/B sound investigation on the Tab5, guided by the Mac service (mock first, then a live provider), produces a useful, evidence-grounded comparison without the operator touching the Mac during the loop. The existing instrument code can support it and be hardened in place.

**Refuted if:** the operator can't finish without developer help, guidance cites the wrong capture, changed settings make the comparison misleading, network waits block local cancel, or the operator can't understand the result or pick a next action.

## Build

1. A fixed fixture where only the A/B variable changes.
2. On-device flow: ask → capture A → guidance → adjust → capture B → an inspectable comparison, with recording/waiting/offline/cancelled/incomplete states visible. Spoken input and guidance, plus text.
3. Mac mock service and device transport. The protocol is in [guided-ab-protocol.md](../guided-ab-protocol.md).
4. Swap in a live model and speech provider behind the same contract. Keys stay on the Mac.
5. Handheld runs, fix blocking defects, review usefulness with the user.

Out of scope: full Explore/Compare breadth, all sensors at once, streaming, calibrated acoustics, hosted deployment, full-duplex speech.

## Checks

1. Host tests cover the state sequence, stale/duplicate/wrong-session rejection, delay, cancel, disconnect and capacity limits.
2. Three mock handheld loops, each with two real captures, guidance, the recorded adjustment and a comparison joined to those exact captures.
3. Controlled trials: 5 s delayed reply, cancel while pending, service disconnect/reconnect. The UI stays live and old-session replies can't act.
4. **Three live-provider handheld loops**, each with capture/transfer/inference/first-response timing. The operator rates responsiveness and usefulness 1–5 (target ≥ 4), states the finding and names a next action unaided.
