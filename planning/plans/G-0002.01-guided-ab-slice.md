## Proposal

### Hypothesis

A single explicit-turn A/B sound investigation on the Tab5, guided through the Mac LAN service first by a scripted mock and then by a live provider, can produce a useful evidence-grounded comparison without requiring the operator to use the Mac during the loop. Existing instrument code can support this product path and subsequently be hardened in place.

### Refuted if

The operator cannot complete the loop without developer intervention; guidance cites the wrong or absent capture; changed settings make the comparison misleading; network waits prevent local cancel; or the operator cannot understand the result or identify a useful next action. Missing captures, transcripts or operator observations are inconclusive, not passes. A reproducible defect requires repair and another retained run, not a waiver.

### Build

Write the corresponding checks below before each implementation step. Inspect current source and Active ADRs before changing ownership or scheduling.

1. Define one reproducible fixture: for example, ask how the recorded sound changes between two distances from a stationary fan. Record device placement, gain, physical audio slot, sample rate and capture duration; change only the stated A/B variable. Do not claim calibrated sound pressure or infer an object's motion from an uncoupled handheld IMU. Freeze the exact fixture and expected comparison before the first run.
2. Implement the smallest complete on-device flow: explicit ask/turn control, capture A, evidence-linked guidance, operator adjustment, capture B, and an inspectable comparison. Show recording, waiting, offline, cancelled and incomplete states. Accept spoken input and provide spoken guidance with visible text; a preset question/text-only path may bootstrap the mock, but does not replace the live handheld loop. Setup may use the Mac; no keyboard intervention during an acceptance loop.
3. Build the Mac Python mock service and real device transport. Reuse the [candidate service architecture](G-0001.04-agent-interaction.md#candidate-service-architecture): device-initiated configurable LAN endpoint, bounded typed commands, boot/session/request/capture identity, deadlines, acknowledgements, cancel and duplicate/stale rejection. The mock must consume actual captures and deterministic measurements, never invent substitute evidence. Keep only the streams needed for this fixture active; record the actual overlap/mode policy rather than claiming full concurrency.
4. Replace only the provider adapter with live model/speech services. Keep keys on the Mac, sanitize logs, and retain the same flow and evidence contract. Provider choice and credential setup require the user; mock development can proceed without them. Start turn-based; label speaker-active intervals and avoid including device playback in A/B measurement windows. Continuous conversation/full-duplex is not implied.
5. Observe the handheld runs, fix blocking defects, and review usefulness with the user. Retain the working implementation, list its measured limits, and map outstanding hardening work back to G-0001. Do not expand this slice into a full sensor dashboard or complete every diagnostic before demonstrating the loop.

### Out of scope

Full Explore/Investigate/Compare breadth, all simultaneous sensors, sustained streaming, calibrated acoustics, hosted deployment and full-duplex speech. The original [concurrency](G-0001.02-concurrent-workload.md), [audio](G-0001.03-audio-integrity.md), [interaction](G-0001.04-agent-interaction.md), [hardware/storage](G-0001.01-hardware-baseline.md) and [power/recovery](G-0001.05-power-recovery.md) gates remain required for G-0001. The slice may use bounded temporary device retention and Mac evidence storage; this does not pass SD or interrupted-write recovery checks.

### How we know

Use the [shared evidence contract](G-0001.01-hardware-baseline.md#shared-run-evidence), with explicit G-0002.01 spec/revision and workload metadata. Preserve failures and private captures; incomplete exports cannot support a conclusion. These are proposed slice checks, not replacements for G-0001's numerical gates.

1. Before the UI/transport build, host tests cover the complete state sequence and reject wrong-session, unknown-capture, expired and duplicate commands. Inject a delayed response, cancellation and disconnection; no stale command may trigger a capture or overwrite the current result. Queue/storage limits must be explicit and tested at capacity. Mock/provider adapters share contract tests.
2. Complete three mock handheld A/B loops. Each must retain the question, two distinct real capture IDs with source settings and hashes, guidance, the recorded operator adjustment and a comparison that joins to those exact captures. Independently check the deterministic measurement values used in the comparison. No fabricated or cross-session evidence, hidden developer intervention, crash or unexplained measurement loss is allowed.
3. In separate controlled mock trials, delay a response by five seconds, cancel a pending turn, and disconnect/reconnect the service. Record local state transitions and their timing; waiting/offline states remain visible, local cancel remains operable, and old-session responses cannot act. This is basic flow validation, not .02's backpressure gate or .04's full cancellation/recovery statistics.
4. Complete three live-provider handheld loops using the same contract. Retain sanitized transcript/evidence joins and timestamps for capture, transfer, inference, first displayed/audible response and cancel where exercised. After each loop the operator gives 1–5 responsiveness/usefulness ratings (proposed target: at least 4 for each dimension in each run), explains the A/B finding, and identifies a next action without developer interpretation. Record latency distributions without claiming .04's 30-turn acceptance from three loops.
5. Close with a requirement-by-requirement result and architecture disposition. Identify reusable implementation/evidence and remaining G-0001 gates. G-0002 is not Met on mock results alone, missing live-provider access, a single polished demo, or unresolved usefulness/integrity failures. Broader reliability remains unproven even if all slice checks pass.
