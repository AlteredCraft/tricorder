# G-0001.04. Agent interaction

Status: In progress
Goal: [G-0001](G-0001-trustworthy-live-investigation.md) — guidance never blocks local instruments.
ADRs: [0010](../adrs/ADR-0010-device-owned-ab-lan-experiment.md), [0011](../adrs/ADR-0011-bounded-tcp-write-completion.md), [0012](../adrs/ADR-0012-live-prose-over-verified-summaries.md), [0013](../adrs/ADR-0013-local-first-speech-to-text.md), [0014](../adrs/ADR-0014-spoken-guidance-streamed-from-the-mac.md)

## Hypothesis

A Python service on the Mac, reached over LAN WebSocket, can guide a capture/compare loop with bounded local response time, correct evidence references, prompt cancel and safe recovery from stale messages or disconnects.

**Refuted if:** network/model waits block instruments, responses cite missing/wrong captures, stale commands act after cancel/reconnect, queues grow during outages, or latency makes the interaction unusable.

## Checks

1. [pass] Protocol: every claim-bearing response joins to stored captures by ID. Unknown/expired/wrong-session commands are rejected; duplicates don't create captures. The same firmware works against two configured endpoints.
2. [open] Mock LAN (≥ 30 turns): command round trip p95 ≤ 200 ms excluding capture/inference; touch-to-submit ≤ 100 ms. 5 s delays and 30 s outages don't block acquisition.
3. [pass] Cancel/recovery (20 trials): cancel-to-playback-stop p95 ≤ 150 ms; no old-session actions; fresh session within 5 s of transport restore.
4. [open] Live (≥ 30 turns): end-of-turn to first audible response p95 ≤ 2.5 s, broken down by stage.
5. [open] Usefulness: three guided A/B sessions without keyboard, each rated ≥ 4/5 for responsiveness and usefulness.

Out of scope: hosted deployment, auth/TLS, multi-user, BLE/Thread. Try WebRTC only if measurements show a WebSocket media limit.
